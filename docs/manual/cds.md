## 0. What this module is, and what it is not

**It is decision *support*, not a decision and not a clearance.** The treating
veterinarian remains responsible for every prescription. The module prints its own
advisory at the foot of every page, in both languages:

> **EN** — "Decision support only. It does not replace clinical judgement, and the
> treating veterinarian remains responsible for every prescription. ⚕️ Verify with
> Dr. Hatem or a licensed vet."
>
> **AR** — «دعم للقرار فقط. لا يغني عن الحكم السريري، والطبيب البيطري المعالج هو
> المسؤول عن كل وصفة. ⚕️ يُرجى التحقق مع د. حاتم أو طبيب بيطري مرخّص.»

**A drug pair that is not one of the 22 interaction rules produces no warning, and
no warning is not the same as "safe".** The engine is a deterministic rule engine
over one curated file holding **20 species contraindications, 4 breed rules, 22
interaction pairs and 36 dose rows** (§5). Everything outside those rules is
silent, not cleared. The screen states this itself when nothing matches — see §4.3.

**The clinical data ships marked as unreviewed.** Every result page prints, in
amber and verbatim, `DRAFT — NOT YET REVIEWED BY A LICENSED VETERINARIAN`, next to
the dataset date `2026-07-25`. Both strings are fields in the data file.

**Nothing is generated by an AI here.** The blueprint reads one JSON file and calls
no model and no network; the page says so: *"Rule engine only — no AI generated any
statement on this page." / «محرك قواعد فقط — لم يُولِّد الذكاء الاصطناعي أي عبارة في
هذه الصفحة.»* The separate `/ai/drug-interactions` banner on the visit screen is a
different, AI-backed check that shares no data and no logic with this module (§9).

## 2. Who can open what

**Every signed-in user, of every role, can open every route in this module.**

Two gates normally apply platform-wide. Here, neither bites:

1. **The module grant.** `login_required` looks up the permission key governing the
   blueprint. `cds` is not one of the 25 keys in `ALL_PERMISSIONS`, so
   `_permission_for("cds")` returns `""`, and a blank key means "nothing can govern
   this blueprint, so do not enforce". The gate falls open by design — the comment
   at `_permission_for` explains why: enforcing against a key no administrator can
   grant would lock users out of a permission that cannot be given.
2. **A route role list.** None of the three routes carries `role_required`.

| Screen / action | Route | Role list on the route | Who can actually use it |
|---|---|---|---|
| The page | `GET/POST /cds/` | none (login only) | every signed-in user |
| Screen (JSON) | `POST /cds/api/screen` | none | every signed-in user |
| Dose (JSON) | `POST /cds/api/dose` | none | every signed-in user |

The launcher card is offered to `super_admin, clinic_owner, branch_manager, doctor,
nurse, pharmacist` only, so other roles get no card — but the URL, the pet-record
link and the prescription hand-off all work for them.

Signing in is still required. A signed-out request is flashed
*"Please log in to continue."* and redirected to the login page; a lapsed session is
flashed *"Your session has expired. Please log in again."*

## 3. Things that apply to every screen

- **Nothing is ever written.** `routes.py` imports `json`, `os`, `re`, `dataclasses`,
  `decimal`, `typing`, three Flask helpers, the blueprint and `login_required` — and
  no database module. No audit row, no note, no flag, no history, no notification.
  A check that was run and one that was not are indistinguishable afterwards.
- **No AI, no network, no database.** The engine is pure: it works with the AI
  service switched off, offline, or unreachable.
- **CSRF.** Every POST needs a token — the hidden `_csrf_token` field on the page
  form, or an `X-CSRF-Token` header for the JSON endpoints. Missing or stale gives
  **HTTP 403 with the HTML error page** *"Invalid or missing security token. Please
  go back and try again."* — an HTML page even for a JSON request.
- **Bilingual.** Labels come from `t(en, ar)` and switch on the signed-in user's
  language; with `lang=ar` the document is `dir="rtl"` and each alert card is forced
  to `direction:rtl`. Every clinical string in the data file carries both an `en`
  and an `ar` value. What stays English is listed in §4.7.
- **Severity is never signalled by colour alone.** Each level carries a distinct
  glyph, an explicit text label, and a distinct border weight and style, so it
  survives colour-blindness, dark mode and greyscale printing (§4.6).
- **Print.** The only print support is `@media print { .cds-alert { break-inside:
  avoid } }`. There is no print view and no export.

## 4. Screen: Clinical Decision Support

**Purpose.** Screen one or more medications against species contraindications,
breed rules and drug-drug interactions for a patient, and — if a weight is given —
print a weight-based dose range for each.

**How to reach it.** Any of the four doors in §1.

**Who can open it.** Every signed-in user (§2).

**Page furniture.** Title `Clinical Decision Support / دعم القرار السريري`,
subtitle `Species contraindications · Drug interactions · Weight-based dosing /
موانع الاستعمال حسب النوع · التداخلات الدوائية · الجرعة حسب الوزن`.

`GET` renders the empty form plus the advisory footer. `POST` renders the same form
(refilled with what you submitted) plus the results.

### 4.2 What the server does with the form

1. `drugs` is split on newline, comma and semicolon; blanks are dropped.
2. For each name: cleaned (lowercased, punctuation dropped, strengths and dosage-form
   words removed), then matched **exactly** against the alias table (§7).
3. Species and breed contraindications are checked for each drug (§5).
4. All recognised drugs are screened pairwise for interactions, plus a duplicate-
   therapy check (§5).
5. Alerts are de-duplicated and sorted worst-first.
6. If a weight was given, a dose is computed for each drug (§6).
7. The page renders. Nothing is stored.

> Source: `platform/blueprints/cds/routes.py:526-558, 585-602`

## 5. The rule set — exactly what the engine knows

Everything the module can possibly say comes from `blueprints/cds/drug_data.json`
(~70 KB), loaded once at import. Every row carries a `source` citation; the file's
own editing rules require one — *"If you cannot cite it, do not add it."*

| Table | Rows | Covers |
|---|---:|---|
| `species_contraindications` | **20** | "Do not give X to species Y" — 15 `contraindicated`, 5 `major` |
| `breed_contraindications` | **4** | Breed/genotype rules — 2 `contraindicated`, 1 `major`, 1 `caution` |
| `interactions` | **22** | Drug pairs — 3 `contraindicated`, 9 `major`, 9 `moderate`, 1 `caution` |
| `doses` | **36** | 19 drugs × dog (18) / cat (17) / rabbit (1) |
| `drug_classes` | **6** | One rule can stand for a whole class |
| `aliases` | **172 keys → 79 canonical drugs** | Trade names, generics, 17 Arabic names |
| `species_aliases` | **41 keys → 8 species** | dog, cat, rabbit, guinea_pig, hamster, bird, turtle, fish |
| `species_weight_range_kg` | **8** | Plausibility bounds for the weight sanity check |

**46 clinical rules in total.** It is a hand-curated shortlist, not a formulary and
not an interaction database.

### 5.2 Breed contraindications (all 4)

All are dogs. Three are the MDR1/ABCB1 story.

| Drug | Gene | Severity | Breed words |
|---|---|---|---|
| ivermectin | ABCB1 (MDR1) nt230(del4) | contraindicated | 15: collie, border collie, australian shepherd, miniature american shepherd, shetland sheepdog, sheltie, old english sheepdog, english shepherd, german shepherd, longhaired whippet, long-haired whippet, silken windhound, mcnab, white swiss shepherd, herding |
| loperamide | ABCB1 (MDR1) | contraindicated | 12: as above, without the miniature american shepherd, the white swiss shepherd and the hyphenated whippet |
| moxidectin | ABCB1 (MDR1) | major | 12: as loperamide |
| trimethoprim_sulfonamide | *(none)* | caution | doberman, dobermann, miniature schnauzer, samoyed |

Three outcomes when a drug has a breed rule for the given species:

- **breed text contains a listed word** → the rule fires at its own severity;
- **breed box empty** → a `caution` card instead: *"No breed recorded for this
  patient. ivermectin has a breed-specific contraindication (ABCB1 (MDR1)
  nt230(del4)) — confirm the breed before prescribing."* / «لم تُسجَّل سلالة هذا
  المريض. للدواء ivermectin مانع استعمال مرتبط بالسلالة — يجب تأكيد السلالة قبل
  الوصف.»
- **breed given but not on the list** → nothing at all.

Matching is a plain substring test on the cleaned breed text, so `Rough Collie`
matches `collie`. It is **not** symmetric: the rule word must be inside your text.

Order does not matter — both directions are checked. A class-versus-itself rule

the duplicate-therapy check instead. **Interactions never consult the species** —
the same 22 rules fire in a hamster and a dog.

**Duplicate therapy** is a built-in rule, not a data row: two different strings
resolving to the same canonical drug produce a `major` alert — *"Rimadyl" and
"Carprofen" are both carprofen — duplicate therapy. The patient would receive a
double dose.* / «"Rimadyl" و"Carprofen" كلاهما carprofen — ازدواج علاجي؛ سيتلقى
المريض ضعف الجرعة.» Two identical strings do not trigger it.

### 5.6 What is NOT covered

The data file carries its own gap list, `_KNOWN_GAPS`. **It is never shown on any
screen** and exists in English only. Verbatim:

1. **No horses, cattle, sheep, goats, camels, pigs or poultry. Food-animal
   withdrawal periods are NOT covered at all.**
2. No chemotherapy, no anaesthetic agents, no euthanasia agents, no fluid therapy,
   no CRI rates.
3. No pregnancy, lactation or paediatric dose adjustment.
4. No renal or hepatic dose adjustment — a patient with CKD or liver disease needs
   doses the engine does not compute.
5. Interaction coverage is a curated shortlist of high-yield pairs, not a complete
   interaction database.
6. No non-drug toxins (xylitol, chocolate, lilies, grapes, rodenticide) — this is a
   prescribing tool, not a poison centre.
7. Acepromazine in Boxers was deliberately left out: the classical warning is not
   supported by recent evidence and the authors chose to omit rather than assert.
8. Isoxazolines (fluralaner, sarolaner, afoxolaner) are named as alternatives but
   have no dose entries.
9. **Bird and fish dosing is absent entirely.**

Read from the code, these further limits hold and are not in that list:

- **No age, sex, body condition, current diagnosis, or concurrent-drug input to a
  dose.** A dose depends on drug, species and weight — nothing else (§6).
- **No course length, no total-course ceiling, no volume in mL, no tablet count.**
- **No frequency arithmetic** — nothing checks that your intended frequency times
  the per-dose amount stays under the daily ceiling.
- **No route selection** — the row's own route is displayed and cannot be changed.
- **No drug-food, drug-disease or drug-lab interactions.**
- **A contraindication does not suppress a dose card** (§8.2 case 5).

## 6. How a dose is calculated

### 6.1 The inputs

Exactly three: **drug**, **species**, **body weight in kilograms**. Nothing else is
read, and nothing else can be supplied.

### 6.2 The formula

The engine finds the one row in `doses` where `drug == canonical drug` **and**
`species == canonical species`. There is no fallback and no interpolation. Then:

```
min_total        = min_per_kg          × weight_kg
max_total        = max_per_kg          × weight_kg
max_daily_total  = max_per_kg_per_day  × weight_kg      (only if the row has one — 35 of 36 do)
```

- **Units.** 35 of the 36 rows are milligrams, so the totals are mg and the per-kg
  line prints as e.g. `0.1-0.3 mg/kg`. Insulin is the exception and its unit
  handling is wrong — see Known limits #4.
- **Arithmetic is `decimal.Decimal` throughout**, built from the quoted strings in
  the data file. Every number in `drug_data.json` is stored as text specifically so
  no value passes through a binary float; the file's editing rules say so and tell
  editors to keep the quotes.
- **Display rounding:** each printed number is quantised to **4 decimal places**
  (Python's default banker's rounding), trailing zeros trimmed, printed in plain
  notation. `0.005 mg/kg × 0.333 kg` prints `0.0017`. The **displayed weight is
  rounded the same way** — enter `12.123456789` and the card says `12.1235 kg`
  though the full value was used in the multiplication.

Worked example — a 4.2 kg cat, meloxicam: `0.1 × 4.2 = 0.42`, `0.3 × 4.2 = 1.26`,
daily ceiling `0.3 × 4.2 = 1.26`. Card: **`0.42 – 1.26 mg`**, `single dose only`,
`0.1-0.3 mg/kg · Do not exceed 1.26 mg/day`, plus the row's note and citation.

### 6.3 The weight plausibility check

Before the arithmetic, the weight is compared against `species_weight_range_kg`:

| Species | min kg | max kg |
|---|---:|---:|
| dog | 0.5 | 100 |
| cat | 0.4 | 12 |
| rabbit | 0.4 | 9 |
| guinea_pig | 0.3 | 1.6 |
| hamster | 0.02 | 0.3 |
| bird | 0.01 | 15 |
| turtle | 0.02 | 120 |
| fish | 0.001 | 50 |

Outside the range, a `major` alert is attached to the dose card:

> **EN** — `4200 kg is outside the plausible weight range for a cat (0.4-12 kg).
> Check the weight and the units before giving this dose — a mis-keyed weight is a
> common cause of overdose.`
> **AR** — «الوزن 4200 كجم خارج المدى المنطقي لهذا النوع (cat: 0.4-12 كجم). تحقق من
> الوزن ووحدته قبل الإعطاء — خطأ إدخال الوزن سبب شائع لفرط الجرعة.»

⚠️ **The dose is printed anyway.** A cat's weight entered in grams — `4200` instead
of `4.2` — produces a fully formatted card reading `420 – 1260 mg` next to that
warning. The warning is the only thing between that card and a thousandfold
overdose.

### 6.4 When the engine refuses

The engine **refuses rather than extrapolates**. Checks run in this order; the first
that applies is the only message shown.

| # | Condition | Message (EN) | Message (AR) |
|---|---|---|---|
| 1 | Drug not in the alias table | `"Zorbaxifen" is not in the clinical database, so no dose can be calculated. Never extrapolate a dose from another drug or another species.` | «الدواء "Zorbaxifen" غير موجود في قاعدة البيانات، ولا يمكن حساب الجرعة. لا يجوز إطلاقًا اشتقاق الجرعة من دواء آخر أو نوع آخر.» |
| 2 | Read as a combination product | `"…" was read as a combination product (ivermectin, praziquantel). Dose each active ingredient separately from the product label.` | «تمت قراءة "…" كمستحضر مركّب (…). يجب حساب جرعة كل مادة فعّالة على حدة من نشرة المستحضر.» |
| 3 | Species not recognised | `Species "Ferret" is not recognised. Dose ranges are species-specific and are never carried across species.` | «النوع "Ferret" غير معروف. مدى الجرعات يختلف حسب النوع ولا يُنقل بين الأنواع.» |
| 4 | Weight missing, non-numeric, zero or negative | `Weight "abc" is not a usable body weight in kg.` | «الوزن "abc" غير صالح كوزن جسم بالكيلوجرام.» |
| 5 | No row for this drug/species pair | `No dose entry for amoxicillin in rabbit. This tool will not extrapolate a dose from another species — use a current formulary.` | «لا توجد جرعة مسجلة لـ amoxicillin في rabbit. لن تُشتق الجرعة من نوع آخر — يُرجى الرجوع إلى مرجع دوائي حديث.» |

A blank species renders as `(blank)` / `(فارغ)`; a blank weight renders as
`Weight ""`. Case 4 accepts Arabic-Indic digits (`٤` reads as 4) but **rejects a

⚠️ Case 4 is rarely visible on the page: a completely empty weight box removes the

for a non-empty but unusable value — `0`, `abc`, `4,2` — or via `/cds/api/dose`.

Case 5 is what a bird, a fish, a hamster, a guinea pig and a turtle always get, and
what **60 of the 79 recognisable drugs** always get.

## 7. How a drug name is matched

Matching is **deliberately exact, never fuzzy**. The code comment gives the reason:
edit-distance matching would confuse prednisone with prednisolone and amikacin with
amoxicillin, and a wrong match that silently fails to warn is the dangerous outcome.

1. **Clean.** Lowercase; strip everything that is not a digit, a Latin letter, an
   Arabic letter or `%`; drop any token that is purely numeric (`500`, `1.5mg`,
   `2x`); drop any token in a 99-word noise list — dosage forms (`tablets`,
   `suspension`, `injection`, `spot-on`), units (`mg`, `mcg`, `iu`, `ml`), routes
   (`po`, `sc`, `iv`, `im`, `otm`), filler (`for`, `and`, `plus`, `with`), species
   words (`dog`, `cat`, `puppy`), sizes (`small`, `large`, `forte`), and 13 Arabic
   packaging words (`بيطري`, `أقراص`, `شراب`, `حقن`, `مجم`, `مل`, `كبسولات`, `مرهم`, …).
2. **Match.** Scan the remaining tokens as n-grams, **longest first** (up to 3
   tokens), against the 172 alias keys. `amoxicillin clavulanic acid` therefore
   resolves to the combination product rather than to plain amoxicillin.
3. **Decide.**
   - one canonical hit → `matched`;
   - several distinct hits at that length → `combination`: **every component is
     screened separately**, an `ℹ️ Note / ملاحظة` card is added — *"Read as a
     combination product containing: ivermectin, praziquantel. Each component was
     screened separately — confirm this is correct."* / «تمت قراءته كمستحضر مركّب
     يحتوي على: … فُحص كل مكوّن على حدة — يُرجى التأكد من صحة ذلك.» — and the dose
     is **refused** for that line;
   - no hit → an `unverified` alert (§8.2 case 1);
   - nothing left after cleaning → treated as empty and dropped.

Worked results, verified against the engine: `Metacam 1.5mg/ml` → meloxicam;
`Synulox 250mg Tablets` → amoxicillin_clavulanate; `Panadol 500mg Tablets` →
paracetamol; `باراسيتامول` → paracetamol; `K9 Advantix spot-on` → permethrin;
`Ivermectin and Praziquantel tablets` → combination (ivermectin + praziquantel);
`prednisolon` → **no match** (a one-letter typo is not forgiven).

To add a trade name, add it to `aliases` in the data file. Do **not** create a new
drug key — the file's editing rules say so explicitly.

## 8. Errors and edge cases

### 8.1 HTTP-level

| Situation | Result |
|---|---|
| Not signed in | Flash *"Please log in to continue."*, redirect to the login page |
| Session lapsed | Flash *"Your session has expired. Please log in again."*, redirect |
| POST without a valid CSRF token | **403** with the HTML page *"Invalid or missing security token. Please go back and try again."* — HTML even for `/cds/api/*` |
| `GET` on `/cds/api/screen` or `/cds/api/dose` | **405** |
| Weight around 10²⁴ kg or above (e.g. `1e24`) | Uncaught `decimal.InvalidOperation` → **500**, rendering *"An internal error occurred. Please try again."* and firing an error alert. Ordinary long numbers are fine (`999999999999999999999999` returns a dose) |

### 8.2 Engine-level

1. **Unrecognised drug** → `unverified` alert, dashed amber border:
   > **EN** — `"Zorbaxifen" is NOT in the clinical database. No contraindication,
   > interaction or dose check has been performed for it. This is not a statement
   > that it is safe — check a current formulary manually.`
   > **AR** — «الدواء "Zorbaxifen" غير موجود في قاعدة البيانات السريرية. لم يتم إجراء
   > أي فحص لموانع الاستعمال أو التداخلات أو الجرعة. هذا لا يعني أنه آمن — يجب
   > المراجعة يدويًا في مرجع دوائي حديث.»

   The name also appears in the headline's `Not checked at all: / لم يُفحص إطلاقًا:` list.

2. **Unrecognised species** → `unverified` alert, and the contraindication check for
   that drug **stops there**: no species rule and no breed rule is evaluated.
   Interaction screening still runs, because it never uses the species.
   > **EN** — `Species "Ferret" was not recognised, so NO species contraindication
   > check was performed. Species-specific lethality is the most important check
   > this tool does — set the species on the patient record and re-run.`
   > **AR** — «لم يتم التعرف على النوع "Ferret"، لذلك لم يُجرَ أي فحص لموانع الاستعمال
   > حسب النوع. يُرجى ضبط نوع الحيوان في ملف المريض وإعادة الفحص.»

3. **No rule matched** → green ✅ headline with the "this is NOT a statement that
   the combination is safe" paragraph (§4.3).

4. **No medications submitted.** The textarea is `required`, so a browser blocks it.
   A POST that bypasses the browser, or a JSON call with no `drugs`, is accepted and
   returns `checked_count: 0`, no alerts and the green `No rule triggered` headline —
   an empty screen that looks like a clean screen. Verified against the route.

5. **A contraindicated drug still gets a dose card** whenever a dose row exists. The
   contraindication block and the dose block do not consult each other. Meloxicam in
   a cat shows both a `Major risk` card and a full dose card.

6. **A drug name containing a comma** is split in two by the page form (which splits
   on newline, comma and semicolon). One drug per line avoids it. The JSON endpoint
   does not split a proper list.

## 10. Editing the clinical data

The data file is designed to be edited by a veterinarian, in plain JSON, without
Python. Its own `_README_FOR_VETERINARIANS` states the rules (bilingual EN/AR):

1. Every entry MUST have a `source`. If you cannot cite it, do not add it.
2. All numbers are written as **text in quotes** (`"12.5"`, not `12.5`). This is
   deliberate — it keeps dose arithmetic exact. Keep the quotes.
3. `drug` and `species` values must be lowercase canonical keys. Add trade names,
   synonyms and Arabic names to `aliases` instead of creating a new drug.
4. Severity must be one of `contraindicated`, `major`, `moderate`, `caution`.
5. A drug absent from this file produces a **loud "not in database" warning**.
   Absence never means "safe". **Do not delete an entry to silence an alert.**
6. After editing, run `pytest tests/test_cds.py`.

That test file is the module's safety specification: 69 tests, opening with the
three that kill — paracetamol in cats, permethrin in cats, ivermectin in an MDR1
herding breed. The file is loaded once at import, so **the application must be
restarted** for an edit to take effect.

> `platform/blueprints/cds/routes.py:45-63`; `platform/tests/test_cds.py`

## Known limits

Things in this module that do not work, are unfinished, or do not match their own
labels. Each is stated with where to verify it. Several are clinically material and
are marked ⚠️.

### Clinically material

1. ⚠️ **A green tick appears whenever no rule fires.** The headline shows `✅` and
   `No rule triggered / لم تُفعَّل أي قاعدة` for a combination the rule set simply does
   not cover. The paragraph beside it says so in both languages, but the icon reads
   as an all-clear at a glance. (`index.html:126-141`)
2. ⚠️ **A blank weight silently removes the entire dose section**, with no message.
   Nothing distinguishes "no dose needed" from "you forgot the weight".
   (`routes.py:543`, `index.html:174`)
3. ⚠️ **A weight outside the plausible range still produces a dose.** The `major`
   warning is attached, and the numbers are printed next to it. A cat weighed in
   grams gets a card reading `420 – 1260 mg`. (`routes.py:491-522`)
4. ⚠️ **Insulin's dose card prints the wrong unit.** The row stores
   `"units": "IU/kg"` and the engine treats that whole string as the unit of the
   *total*: for a 5 kg cat the card reads **`1.25 – 2.5 IU/kg`** when the number
   means 1.25–2.5 IU in total, and the grey line reads **`0.25-0.5 IU/kg/kg`**. The
   row has no daily ceiling, so no `Do not exceed` line is drawn either. Read the
   numbers as IU and ignore the `/kg`. The row's own note is correct.
   (`routes.py:49-59, 512, 516-518`; verified against the engine)
5. ⚠️ **The hyphenated `long-haired whippet` breed entry can never match.** Typed
   breeds are stripped of punctuation before comparison (`Long-haired Whippet` →
   `long haired whippet`) while the rule's breed strings are not. Typing
   `Long-haired Whippet` produces **no MDR1 warning** for ivermectin; typing
   `Longhaired Whippet` does. (`routes.py:194-199, 336`; verified)
6. ⚠️ **A contraindicated drug still gets a dose card** whenever a dose row exists.
   Meloxicam in a cat shows a `Major risk` contraindication and a full dose card side
   by side, with nothing suppressing the second. (`routes.py:526-543`)
7. ⚠️ **Four of the six drug classes are defined but referenced by no rule** —
   `aminoglycoside`, `macrocyclic_lactone`, `azole`, `fluoroquinolone`. Gentamicin or
   amikacin with furosemide warns; **neomycin or tobramycin with furosemide produces
   nothing**. (`drug_data.json` → `interactions` versus `drug_classes`)
8. ⚠️ **`_KNOWN_GAPS` — the module's own statement of what it does not cover — is
   never displayed**, and exists in English only. The clinicians who most need §5.6
   cannot read it from the screen. (`drug_data.json` → `_KNOWN_GAPS`)
9. ⚠️ **A zero-drug screen renders the green `No rule triggered` headline** with
   `checked_count: 0`. Reachable through the JSON endpoint or a form POST that
   bypasses the browser's `required` check. (`routes.py:528, 552`)
10. ⚠️ **`Guinea pig` is a CDS species with six antibiotic contraindication rules,
    but is not an option on the pet record form** (`Dog, Cat, Rabbit, Bird, Hamster,
    Fish, Turtle, Other`). A guinea pig recorded as `Other` does not resolve, so
    those rules are never reached through the prescription hand-off — you get the
    "Species … was not recognised" alert instead. Type `Guinea pig` into the CDS
    form by hand. (`crm/pet_form.html:206-213` versus `drug_data.json` →
    `species_aliases`)
11. ⚠️ **The data file ships as DRAFT and unreviewed.** Until a licensed veterinarian
    signs it off, treat every row as a prompt to check the citation, not as the
    citation. (`drug_data.json` → `review_status`)

### Not implemented at all

12. **Nothing is ever recorded.** No audit row, no note, no flag, no history. There is
    no way to demonstrate afterwards that a screen was run. (`routes.py:25-35`)
13. **The prescription banner never changes** — it reads `❔ Not screened / ❔ لم يتم
    الفحص` before and after you screen, because nothing is written back.

16. **No accept / dismiss / acknowledge / override control.** The page is a reference,

17. **The two JSON endpoints are called by nothing.** `api_screen`'s docstring says it

18. **No frequency arithmetic.** A card can show a per-dose maximum, a frequency of

23. **A comma decimal separator is rejected** — `4,2` refuses with `Weight "4,2" is
