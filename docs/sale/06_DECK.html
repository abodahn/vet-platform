04 — The problem

The incumbent is a paper notebook and a WhatsApp thread

It works, right up to the week the clinic hires its second vet. Then nobody knows which animal was seen, what was dispensed from the shelf, or who is owed what.

What breaks first

  • Two people writing in one notebook
  • Stock counted by looking at the shelf
  • Vaccine reminders remembered, not scheduled
  • The month's takings reconstructed from memory

Why software has not replaced it

  • Priced in dollars, for practices ten times the size
  • English-only interfaces, in an Arabic-speaking clinic
  • Arabic that breaks the moment it is printed
  • Modules sold separately: the shop, the salon, the payroll

07 — Differentiator

Arabic all the way to paper

Four things must be right for Arabic to survive onto a printed invoice. All four are — including the one almost nobody finds.

The three most people get

  • A translated interface — 5,219 t(en, ar) pairs
  • Right-to-left layout that mirrors, not just aligns
  • A font in the PDF that contains Arabic glyphs at all

The fourth

Arabic letters change shape by position, and joining is done by the font's ligature tables. A font missing one ligature prints a word that is legible-but-wrong to a clinic and invisible to the developer who cannot read it.

That class of bug was found and fixed at the level of a specific font's missing ligature. A translation project does not reach this.

08 — Differentiator

Breadth is the moat, not any single module

No competitor identified in our own market research covers grooming and boarding and payroll and retail in one system.

A clinic that grooms, boards, sells food and employs six people is running four products and reconciling them by hand. This is one database, one login, one set of numbers — and the retail till posts into the same ledger as the consultation.

The honest version of this claim

Competitors have things this does not: lab-machine integrations and a pet-owner mobile app, among others. The buyer for this asset wants the breadth and the source — not to win a feature comparison.

09 — Differentiator

One command per clinic

python scripts/add_clinic.py --slug nilevet --name "Nile Vet Clinic"

That provisions a clinic: its own database, its own schema, its own first administrator, reachable on its own subdomain.

For a software house acquiring this, onboarding cost is the number that decides whether a vertical product is a business or a consultancy. This one is a command and a DNS record.

10 — Differentiator

Isolation is physical, not a WHERE clause

Every clinic gets its own database. Not a shared table with a tenant column — a separate database, resolved by subdomain before the first query runs.

Shared-table multi-tenancy

One forgotten WHERE tenant_id = ? in any one of hundreds of queries shows one clinic another clinic's medical records. The bug is invisible until it is a breach.

Database per clinic

A missing WHERE cannot cross a database boundary. The isolation does not depend on every query being written correctly forever.

A session also carries the clinic it was issued for, so a cookie minted at one clinic is refused at another.

12 — Proof of rigour, in one story

A reports page showed 334,070 EGP of real sales as zero

The pet shop had 172 completed orders on the books. Every report read zero.

-- every aggregate filtered on one spelling of the status
WHERE status = 'paid'

-- every order in the database carried
status = 'completed'

The sale-creation code wrote 'paid'. The live data said 'completed'. So whichever spelling a row happened to have, an entire set was invisible — and the page looked like it was working, because it rendered a number.

Seven filters now count every order that is not cancelled or refunded. 0.00 EGP → 334,070.00 EGP, verified against the live database.

This is the slide to rehearse. It is the only one where a non-technical buyer feels the value of the engineering rather than being told about it.

13 — What is not there

Stated first, because diligence finds all of it anyway

The discovery costs more than the disclosure. None of the following is softened.

Commercial

  • Zero customers, zero revenue, no operating history
  • No reference customer, testimonial or site visit to offer
  • No support contract, SLA or ticket history
  • No trademark registration for the name
  • No e-invoicing accreditation with the Egyptian Tax Authority
  • One demo clinic, and its data is synthetic

Product

  • WhatsApp has never been sent end to end. The transport is real and unified; no message has provably reached a phone from this code
  • Online card payments are unverified
  • No client portal or online booking
  • 34 money columns are floats; the migration is written and deliberately unapplied
  • The PostgreSQL CI job is non-blocking — one hardcoded database name

A credential reached the git history. It cannot be removed from history, only rotated — it has been, a test now blocks a new one from being committed, and it is disclosed here rather than left to be found.

Anyone valuing this on Egyptian ARR alone should not buy it. The asset is a finished, Arabic-complete vertical product that a MENA software house can monetise across several markets — where a consultation fee is two to nine times the Egyptian one, and the localisation work is already done.

Jordan, Iraq and Lebanon run on the existing Arabic/English build unchanged. Morocco, Algeria and Tunisia would need French — the vets there are trained French-medium. That is in our research, not discovered by a buyer afterwards.
